Overview

What Is Cronas?

Cronas Engine is a production-grade delayed webhook delivery service. Clients submit a job — a target URL, HTTP method, optional payload, and a future scheduled time — via a REST API. The engine persists the job to PostgreSQL, then a cluster of nodes races to execute it at the correct moment.

The hard problem is distributed coordination: when multiple nodes poll the same database table simultaneously, only one node must fire the webhook. Cronas solves this with two independent, layered contention barriers.

Features

Why Cronas?

Exactly-Once Delivery

Dual-layer contention prevention with PostgreSQL SKIP LOCKED and Redis distributed locking guarantees every webhook fires precisely once.

Virtual Threads

Java 21 Project Loom virtual threads handle thousands of concurrent outbound HTTP requests with negligible OS resource overhead.

Horizontally Scalable

Scale to any number of nodes with a single docker-compose up --scale command. Fully stateless polling and execution logic.

Fault Tolerant

Exponential backoff retry with dead letter queue. Failed jobs are never silently discarded — they remain available for post-mortem inspection.

Full Observability

Prometheus + Grafana pipeline with auto-discovery of scaled containers. Monitor HikariCP, JVM heap, GC, and virtual thread utilization out of the box.

One-Command Deploy

The entire stack — Postgres, Redis, app cluster, Prometheus, Grafana — runs from a single docker-compose up command.

Architecture

How It Works

Clients submit jobs via REST API. The cluster polls PostgreSQL every second, distributing rows across nodes with SKIP LOCKED, then applying Redisson distributed locks for final mutual exclusion before firing the webhook.

Technical Deep Dive

Under the Hood

Dual-Layer Contention Prevention

The polling loop runs on every node in the cluster every 1,000 ms. Without coordination, every node would attempt to execute every eligible job simultaneously. Cronas prevents this at two independent layers.

Layer 1 — PostgreSQL SKIP LOCKED

SQL — Polling Query 
SELECT * FROM jobs
WHERE state = 'PENDING'
AND scheduled_time <= NOW()
LIMIT 100
FOR UPDATE SKIP LOCKED;

Layer 2 — Redisson Distributed Lock

Java — Redis Lock Acquisition 
RLock lock = redissonClient.getLock("cronas:lock:" + job.getJobId());
if (lock.tryLock(0, 15, TimeUnit.SECONDS)) {
    // Only one node reaches here per job
    webhookExecutor.fireWebhook(job);
}

Java 21 Virtual Threads (Project Loom)

The JobPoller dispatches every job onto a virtual thread via Executors.newVirtualThreadPerTaskExecutor(). Virtual threads are lightweight, JVM-managed threads that park rather than block on I/O, allowing thousands of concurrent outbound HTTP requests with negligible OS resource consumption.

Java — JobPoller.java 
private final ExecutorService virtualThreadExecutor =
    Executors.newVirtualThreadPerTaskExecutor();

@Scheduled(fixedDelay = 1000)
public void pollAndExecute() {
    List<Job> ripeJobs = jobRepository.findExecutableJobsWithLock(100);
    for (Job job : ripeJobs) {
        virtualThreadExecutor.submit(() -> processJobSafely(job));
    }
}

Exponential Backoff & Dead Letter Queue

A failed webhook is not discarded. The retry state machine applies binary exponential backoff (1m → 2m → 4m → 8m…) before rescheduling. Once retryCount ≥ maxRetries, the job is permanently transitioned to FAILED — the dead letter queue pattern. Failed jobs remain in the database for post-mortem inspection.

Java — Retry Logic 
long delayMinutes = (long) Math.pow(2, currentRetries); // 1m → 2m → 4m → 8m…
job.setScheduledTime(Instant.now().plus(delayMinutes, ChronoUnit.MINUTES));
job.setState(JobState.PENDING); // Re-enters the polling queue

Quick Start

Get Running in Minutes

Prerequisites: Docker and Docker Compose.

1

Clone the repository

bash 
git clone https://github.com/mihirvr/cronas.git
cd cronas
2

Build and launch the full stack

bash 
docker-compose up --build --scale cronas-app=3
3

Schedule your first webhook

bash 
curl -X POST http://localhost:9090/api/v1/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "targetUrl": "https://webhook.site/your-endpoint",
    "httpMethod": "POST",
    "payload": "{\"event\": \"order.confirmed\"}",
    "scheduledTime": "2025-12-01T14:30:00Z",
    "maxRetries": 3
  }'
